\###  Задача №4: Подвійний переворот числа (LeetCode 2117)

\- \*\*Як працює:\*\* Алгоритм перевіряє, чи повернеться число у початковий вигляд після двох перевертань задом наперед.

&#x20;Число втрачає розряди тільки тоді, коли закінчується на нуль (наприклад, 1800 після першого перевертання втрачає нулі попереду, перетворюючись на 81, а потім на 18).

&#x20;Метод миттєво відловлює це правило через швидку перевірку умови `num == 0 || num % 10 != 0`.



\- \*\*Навіщо це в житті:\*\* Це критичний захист від \*\*втрати даних при конвертації між сервером і базою даних\*\*. Коли веб-додаток відправляє зашифрований унікальний ID користувача чи токен сесії (наприклад, `ID = 85400`), через несумісність форматів чи кривий код нулі наприкінці можуть "відвалитися" як порожнє місце.

&#x20;Система на виході отримає зламаний ID `854`, користувач втратить доступ до свого акаунту, а в логах вилетить помилка авторизації.
