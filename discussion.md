# Практична №1 — Відкрита дискусія

1. Чим програма відрізняється від алгоритму?
Алгоритм — це послідовність дій для розв'язання задачі. Програма — запис цих дій мовою програмування для виконання комп'ютером.

2. Навіщо потрібні мови програмування, якщо процесор їх не розуміє?
Людині зручніше писати зрозумілий код. Компілятор або інтерпретатор забезпечує його виконання через машинні інструкції.

3. Чи може комп'ютер зробити щось, чого йому не казали?
Він виконує інструкції, але результат може бути неочікуваним через помилки в коді або незвичні вхідні дані.

4. Чи є рецепт борщу алгоритмом?
Так, якщо вказані продукти, їхня кількість і чітка послідовність дій. Фрази на зразок «варити до готовності» потребують уточнення для новачка.

5. Як пояснити зав'язування шнурків тому, хто їх ніколи не бачив?
Шнурок — тонка мотузка, протягнута через отвори взуття. Візьми два вільні кінці, перехрести їх, проведи один під іншим і затягни. Склади кожен кінець удвоє, щоб утворити дві петлі. Перехрести петлі, проведи одну під іншою через отвір між ними та потягни обидві петлі в різні боки.

6. Програма правильно порахувала всі приклади з дошки. Чи доводить це, що вона працює правильно?
Ні, це підтверджує правильність лише на перевірених прикладах. Потрібно перевірити інші випадки та межі допустимих значень; для повного доведення потрібне обґрунтування алгоритму.

# Практична №2 — Представлення цілих чисел

1. Чому комп'ютер рахує двійками, а не десятками, як ми?

Електронним схемам зручно розрізняти два стани сигналу: низьку та високу напругу. Їх позначають як 0 і 1. Із послідовності таких значень можна скласти двійковий запис цілого числа.

2. Що таке біт і чому саме вісім бітів назвали байтом?

Біт — найменша одиниця даних, яка може мати значення 0 або 1. Сучасний байт складається з 8 бітів. Такий розмір став поширеним історичним стандартом, зокрема завдяки комп'ютерам IBM System/360. Вісім бітів дають 256 різних комбінацій, що зручно для кодування даних.

3. Як записати від'ємне число, якщо в пам'яті є лише нулі й одиниці?

У Java цілі знакові числа зберігаються в доповняльному коді. Щоб отримати запис від'ємного числа, інвертують біти відповідного додатного числа та додають 1. Наприклад, у 8-бітному поданні 5 — це 00000101, а -5 — 11111011.

4. Чому виникає переповнення і як з ним боротися?

Переповнення виникає, коли результат обчислення виходить за межі типу. Наприклад, додавання 1 до найбільшого значення int у Java дає -2147483648 замість 2147483648. Потрібно перевіряти межі перед обчисленням або використовувати тип із більшим діапазоном, наприклад long. Для виявлення переповнення під час додавання можна застосувати Math.addExact: цей метод повідомляє про нього винятком.

5. Чому в старих іграх максимум золота — рівно 2 147 483 647?

Якщо гра зберігає кількість золота як 32-бітне знакове ціле число, його найбільше значення — 2^31 - 1, тобто 2147483647. Саме такий спосіб зберігання пояснює цей ліміт. В інших іграх межа може бути іншою.

6. Чому комп'ютер вважає, що 7 / 2 = 3?

У Java числа 7 і 2 мають тип int, тому виконується цілочисельне ділення. Воно відкидає дробову частину результату: із 3.5 залишається 3. Щоб отримати 3.5, потрібно виконати ділення з дробовим числом, наприклад 7.0 / 2.

# Практична №3 — Представлення дробових чисел

1. Навіщо потрібні окремі типи для цілих і дробових чисел?

Цілі типи, наприклад int, зберігають числа без дробової частини точно в межах свого діапазону. Типи float і double дозволяють працювати з дробами, але багато значень зберігають приблизно.

2. Що означає «рухома кома» і куди вона рухається?

Число зберігається через значущу частину та степінь двійки. Степінь визначає масштаб числа, тобто положення коми. Схожий десятковий приклад: 6.25 × 10² = 625. Кома «рухається», коли змінюється степінь.

3. Скільки цифр після коми комп'ютер здатен запам'ятати?

Немає фіксованої кількості цифр після коми. float має приблизно 6–7 значущих десяткових цифр, double — 15–16. Це загальна точність числа, включно з цифрами до коми.

4. Чому 0.1 + 0.2 не дорівнює 0.3?

У двійковій системі 0.1 і 0.2 мають нескінченний дробовий запис. У double вони округлюються, тому результат додавання становить 0.30000000000000004.

5. Чому гроші не варто зберігати у double?

Для грошей потрібні точні суми, а double може давати похибки. Краще зберігати цілу кількість копійок у long або використовувати BigDecimal. Десяткові значення можна задавати рядком, наприклад new BigDecimal("0.1"). Правила округлення потрібно визначати явно.

6. Чи може число не дорівнювати самому собі?

Так, спеціальне значення NaN не дорівнює самому собі при порівнянні через ==. Наприклад, double x = 0.0 / 0.0; дає NaN, а x == x повертає false. Для перевірки використовують Double.isNaN(x).
